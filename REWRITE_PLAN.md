# Web UI Rewrite Plan

Status: **draft for review** — framework deliberately undecided (Phase 1 gate).
Repo: `jlf-web` (fork of `jellyfin-web` 13.0.0, HEAD `51fdffeb60`).
Prepared: 2026-11-06.

This plan does three things in order: (1) states what the repo actually is today,
verified from source and from reverse-engineering (REA) runs; (2) turns the
unfinished framework question into a bounded decision gate with spikes and exit
criteria; (3) sequences the rewrite as an incremental strangler with per-phase
parity gates, so no phase depends on the framework choice being right the first
time.

Two conclusions that shape this plan:

1. **REA's route extractor is not the route inventory.** The modern app defines
   routes as object literals in `routes/*Routes/*.ts`, so the static route view
   recovered 4 patterns where the tables define 24 entries. Route truth must be
   read from the tables (and eventually generated by a script — Phase 0).
2. **Coupling is measurable but the semantic graph is partial.** `src/lib` and
   `src/apps/modern` analyzed cleanly, the legacy tree did not fit the budget.
   Any "what calls what" claim for legacy screens has to be re-derived per
   directory (≤ ~350 KB per REA run) before those screens are ported.

## 2. Current architecture in one page

- One webpack bundle (`main.jellyfin`) is built from `src/index.jsx`, plus one
  chunk per SCSS theme. Output is **static files** served by the Jellyfin server
  (and embedded in desktop/mobile webviews — see `README.md`).
- Two parallel layouts exist in the same bundle and are switched at runtime:
  `components/layoutManager.js` sets `modern = !isLegacyLayout`. `RootAppRouter`
  picks `MODERN_APP_ROUTES` or `LEGACY_APP_ROUTES` accordingly.
- React 18 + MUI + TanStack Query covers the modern app, dashboard, wizard, and
  the public `forgotpassword` page.
- jQuery-era code covers item details, generic lists, lyrics, queue, video
  queue/prefs screens and the metadata editor. It is mounted **inside** React by
  `ViewManagerPage`, and `components/Page.tsx` bridges the two worlds by
  dispatching jQuery-style events (`viewbeforeshow`, `pagebeforeshow`,
  `viewshow`) and calling `viewManager.hideView()`.
- Playback is a singleton (`playbackmanager.js`) driving 15 plugins through
  `window.pluginManager` and `window.Events`.
- Auth/connection is `lib/jellyfin-apiclient` + `connectionManager`, multi-server,
  token-based, with Quick Connect and per-server media tokens.

The rewrite's real problem is not "React vs something else". It is that **the
shell, auth, playback, plugins, i18n and theming are entangled with a hash-routed
static SPA**, and each candidate framework changes how many of those you get to
keep.

## 3. Constraints that decide the framework

These are pass/fail filters, not preferences. A candidate that breaks one of
C1–C6 is out or needs an explicit product decision to change distribution.

| ID | Constraint | Why it is hard | Evidence |
|---|---|---|---|
| **C1** | Ships as **static assets** into the Jellyfin server and third-party webviews | SSR/hypermedia needs a Node/Deno process that does not exist in the current deployment path | `README.md`; webpack static output |
| **C2** | Deep links are hash-based (`#/home`) | Server-rendered routes need path routing + server-side fallback + 301 strategy for old links | `RootAppRouter.tsx` |
| **C3** | Multi-server auth + token injection lives client-side | A BFF must proxy every API call per server, keep sessions, re-implement Quick Connect and media-token rules | `lib/jellyfin-apiclient`, 139 call sites |
| **C4** | 109 locales, client-loaded dictionaries, Weblate pipeline | Server rendering must resolve translations per request or per build without forking the translation workflow | `src/strings/*.json`, `src/lib/globalize` |
| **C5** | JS player/plugin contract (`window.pluginManager`, `window.Events`) | Server-rendered HTML cannot host 15 JS plugins; players must stay islands | `src/plugins/`, `components/pluginManager.js` |
| **C6** | D-pad / keyboard / TV focus model | Focus lives in DOM order and `autoFocuser`; partial HTML swaps destroy it unless explicitly managed | `scripts/keyboardNavigation.js`, `components/autoFocuser` |
| **C7** | Theme contract (SCSS build + runtime CSS vars) | Any server template must emit identical class names and CSS variable hooks | `webpack.common.js`, `src/themes/` |
| **C8** | Service worker (notifications, offline shell) | Caching dynamic HTML is a different problem from caching a static bundle | `src/serviceworker.js` |
| **C9** | No regression safety net (15 test files) | Parity must be measured, not assumed; budget for building it first | §1 |
| **C10** | 20 legacy views + 40 controllers are the expensive tail | Whatever the framework, this tail is rewritten by hand | `apps/legacy/` |

## 4. Phase 1 — Framework decision gate

Do not start page work before this gate closes. Run all five spikes against the
same two screens (public `/login` profile picker, and `/movies` library grid),
because those two exercise auth, i18n, theming, images, filters and TV focus.

### 4.1 Options

| Option | Shape | Keeps | Costs | Fits |
|---|---|---|---|---|
| **A. Finish the React modern app** | Stay React 18 + MUI + Query; port the 8 legacy user routes + dashboard tail; delete `legacy` app | C3, C4, C5, C7, C8 unchanged | Largest JS payload stays; MUI perf on low-end TVs; still hash routing unless changed | C1 ✅ |
| **B. Client-side framework swap** | SvelteKit/Solid/Preact SPA (adapter-static) or Qwik/Astro with full hydration | C1, C4, C5 (islands), C8 | Rewrites shell + components for no server benefit; loses MUI ecosystem; Query/state patterns re-learned | C1 ✅ |
| **C. Hypermedia (HTMX) + BFF** | Node BFF renders fragments; htmx swaps; player + auth stay JS islands | C4 (server i18n), C7, small JS | Breaks C1 unless BFF ships as sidecar; C2 (path routing), C3 (proxy), C6 (focus), C8 all become new work | C1 ❌ unless distribution changes |
| **D. SSR meta-framework** | Next/SvelteKit/Astro SSR + islands, BFF included | Small initial JS, server data loading | Same distribution hit as C, plus framework churn and 109-locale server i18n | C1 ❌ unless distribution changes |

Scoring (1–5, higher better), weighted by the constraints above:

| Criterion (weight) | A | B | C | D |
|---|---|---|---|---|
| Distribution fit C1 (×3) | 5 | 5 | 1 | 1 |
| Auth/server-session fit C3 (×2) | 5 | 5 | 2 | 2 |
| Plugin/player fit C5 (×2) | 5 | 4 | 3 | 3 |
| Legacy-tail effort C10 (×2) | 4 | 3 | 2 | 2 |
| Payload/perf on TV C6/weight (×2) | 2 | 4 | 5 | 5 |
| i18n/theming fit C4/C7 (×1) | 4 | 3 | 2 | 2 |
| Reversibility / risk (×1) | 4 | 3 | 2 | 2 |
| **Weighted total** | **80** | **76** | **44** | **44** |

**Recommendation (to be confirmed by spikes, not assumed):** default to **A**,
with the explicit option to adopt **B**'s rendering layer later behind the same
contract. Choose C or D only if a product decision says the web client may ship
with a Node sidecar (or if a Jellyfin-side template route becomes available);
that decision is outside this repo and must be recorded as an ADR before spiking.

### 4.2 Spikes (each ≤ 3 days, timeboxed, throwaway code under `mockups/spikes/`)

| Spike | Question | Deliverable | Exit criterion |
|---|---|---|---|
| **S1 Shell** | Can the candidate render the app shell (drawer, toolbar, now-playing bar) with the existing theme CSS and no layout shift? | Static page using `src/themes/*` classes | Visual match ≥ 90% of current `/home` at 1280×720 and 1080p TV; no CLS > 0.1 |
| **S2 Auth** | Can login → list libraries → fetch items work in the candidate without duplicating connection logic? | `/login` + `/movies` against a real Jellyfin server | No new auth code outside a thin adapter; token never in HTML |
| **S3 i18n/theming** | Do the 109 locales and user theme/CSS injection work? | Locale switch + custom CSS on the spike screens | 3 locales render without layout break; user CSS applies identically |
| **S4 Player island** | Can `playbackmanager` + `htmlVideoPlayer` + chromecast run unmodified inside the candidate? | Play/pause/seek/subtitles on an HLS and a direct-play item | Player plugin loaded through `pluginManager` unchanged; no fork of `playbackmanager.js` |
| **S5 TV/keyboard** | Does D-pad navigation and focus restore survive the candidate's navigation model? | Arrow-key traversal over the library grid + back button | Every grid cell reachable; focus restored after back; visible focus ring |

Kill criterion for any option: failing S4 or S5 without a documented, bounded
workaround.

### 4.3 Gate outputs

- `docs/adr/0001-web-ui-framework.md` — decision, alternatives, spike evidence.
- `docs/parity-matrix.md` — the route table from Phase 0, annotated with target
  owner (React / island / server) for the chosen framework.
- Updated `SCREEN_FEATURES_INVENTORY.md` (see Phase 0).

## 5. Target architecture (framework-agnostic invariants)

Whatever wins Phase 1, these hold, and phases below assume them:

1. **Route registry is data, not JSX.** One manifest describes every route:
   path, auth level (`public`/`user`/`admin`), data deps, owner. Both the app and
   the parity tests read it. This is what makes the framework swappable.
2. **Auth adapter.** Exactly one module knows about connection manager, tokens
   and per-server URLs. No page calls `apiClient` directly; pages call resource
   hooks/loaders. Today: 139 files break this rule — that is the seam to build
   first.
3. **Playback is an island.** `playbackmanager` stays a singleton behind a
   narrow interface (`play`, `queue`, `seek`, `state`, events). No page owns
   player state.
4. **Plugins stay JS.** `pluginManager` + `window.Events` are preserved verbatim
   in Phase 2 and only re-typed, never re-architected.
5. **Design tokens before components.** Extract the visual contract (spacing,
   color, typography, focus ring) from `src/themes` + `AppOverrides.scss` into
   tokens; components (MUI or otherwise) consume tokens, not the reverse.
6. **Strings are data.** `src/strings/*.json` stays the single source; the
   framework never introduces a second translation format.
7. **URLs keep working.** Old `#/route?query` links redirect to the new scheme for
   at least one release; a route-level redirect table ships with Phase 10.

## 6. Migration strategy

Strangler fig, not big bang. Two entry points are free because they already
exist: the runtime layout switch (`layoutManager.modern`) and the route tables.
Concretely:

- Add a third owner state per route — `legacy` (ViewManager), `react` (modern),
  `new` (rewrite) — resolved from the route registry, not from a global flag.
- Ship routes individually behind a per-user/per-server flag, so a broken screen
  can be reverted without a release rollback.
- Retire code only when its route is `new`, its legacy controller has no other
  importer, and its views/tests are gone.

### 6.1 Route ownership today (modern mode) — the rewrite backlog

| Group | Routes | Owner | Effort |
|---|---|---|---|
| Public | `login`-family (`addserver`, `selectserver`, `login`, `forgotpasswordpin`), `forgotpassword`, `quickconnect` | legacy views + 1 async | S–M (mockup exists) |
| Browsing | `home`, `movies`, `tv`/`shows`, `music`, `books`, `boxsets`, `playlists`, `mixed`, `homevideos`, `musicvideos`, `livetv`, `search` | react | M each (port + re-skin) |
| Item detail | `details`, `list`, `lyrics` | **legacy** | L (largest single screen) |
| Playback | `video` (hybrid: modern controls + legacy view), `queue` | **hybrid/legacy** | L (island) |
| Prefs | `mypreferencesdisplay`, `mypreferencesmenu`, `userprofile`, `mypreferencescontrols`/`home`/`playback`/`subtitles` | react + 4 legacy | M each |
| Dashboard | 28 async, `metadata` editor, `configurationpage` (server-provided) | react + legacy + server | L (tail) |
| Wizard | 6 steps | react | S |
| Mockup coverage | public 7 screens, user 17 fragments | htmx mockups | visual only, no API |

`/details`, `/queue`, `/video` and the metadata editor are >50% of the remaining
effort. Plan them as their own workstreams, not as "pages".

## 7. Phases

Each phase ends with a gate. A gate is a list of checks, not a feeling.

### Phase 0 — Truth up (3–5 days)

1. Write `scripts/inventory-routes.mjs`: parse `apps/*/routes/**` +
   `ViewManagerPage` props and emit `docs/route-registry.json` (path, auth level,
   owner, legacy controller/view, query params).
2. Diff that output against `SCREEN_FEATURES_INVENTORY.md`; correct the doc's
   counts and ownership claims (it currently reads route tables by hand and
   under-reports legacy-mode routes).
3. Stand up the safety net that does not exist yet: Playwright smoke specs for
   the 12 highest-traffic routes (login, home, movies, tv, music, search,
   details, video, queue, prefs, livetv, dashboard), asserting DOM landmarks,
   not pixels.
4. Record baseline perf: bundle size, JS bytes on `/home`, LCP/TBT on a throttled
   TV-class profile.

**Gate 0:** registry regenerates deterministically in CI; smoke suite green on
the unmodified app; baselines committed.

### Phase 1 — Framework gate (see §4)

**Gate 1:** ADR merged; spikes S1–S5 pass or are explicitly waived with owners.

### Phase 2 — Foundations (2–3 weeks, framework-dependent but reversible)

1. Route registry wired into the app as the single route source (replaces the
   two hand-maintained `routes.tsx` trees).
2. Auth adapter: `useResources`/loader layer over `jellyfin-apiclient`; migrate
   `src/lib` + `apps/modern` first, leave legacy on `apiClient`.
3. Design tokens extracted from themes; one stylesheet contract used by both old
   and new screens during transition.
4. Playback island interface + a contract test that `playbackmanager` can be
   driven without a page.
5. Plugin host frozen: typed shim around `pluginManager`/`window.Events`, with
   the 15 plugins loading unchanged.
6. `#/` → `/` URL strategy decided and implemented behind a flag (prepares C2).

**Gate 2:** zero pages regressed; new lint rule blocks new direct `apiClient`
imports outside the adapter; plugin contract test green.

### Phase 3 — Public routes (1–2 weeks)

Port the 7 mocked screens to the chosen framework using real APIs (login, quick
connect polling, forgot-password, PIN reset, add/select server). Reuse the
mockups' visual language; replace the inert forms.

**Gate 3:** login/QC/PIN flows pass e2e against a live server in 3 locales; no
auth token in HTML; media-token path unchanged.

### Phase 4 — Browsing routes (3–4 weeks)

Home, library grids, filters/sort/pagination, alphabet picker, cards. This is
where the card/rendering stack is decided once for all libraries.

**Gate 4:** all 12 browsing routes on `new`; filter+sort+pagination parity vs
baseline; TV focus test passes; image lazy-loading budget met.

### Phase 5 — Item details (3–4 weeks)

The hardest read-only screen: cast/crew, seasons/episodes, similar, versions,
play/resume/shuffle/trailer, context menu, metadata table.

**Gate 5:** feature checklist signed off per media type (movie, series, season,
episode, album, artist, book, boxset, playlist); deep-link + back-stack parity.

### Phase 6 — Playback (3 weeks, parallel with 5)

`/video` + `/queue` with the island: HLS/direct play, subtitles (libass), audio
tracks, chapters, trickplay, syncplay hooks, chromecast/remote play handoff,
still-watching.

**Gate 6:** playback matrix (transcode on/off, direct play, subtitle burn-in,
audio-only, live TV) green on desktop + TV profile; no regression in
`playbackmanager` API.

### Phase 7 — Preferences (2 weeks)

User display/home/playback/controls/subtitles/profile. Mostly forms; use this
phase to establish the form/validation pattern for the dashboard.

**Gate 7:** every setting round-trips to the server; keyboard-only completion;
unsaved-change guarding.

### Phase 8 — Search, Live TV, music (2–3 weeks)

Global search + filters, guide grid, recordings/series timers, music artist/album
views and now-playing bar behaviour.

**Gate 8:** guide scroll/focus performance on TV profile (frame budget); search
debounce/cancel; music continuous play.

### Phase 9 — Dashboard + wizard (4–6 weeks, can start after Gate 7)

28 admin routes, metadata editor, plugin config passthrough, users/permissions,
logs, tasks, libraries. Lowest user traffic, highest form complexity.

**Gate 9:** admin parity checklist per route; permission-denied states (404 not
403) preserved; plugin config pages still render server-provided HTML.

### Phase 10 — Retire legacy (2 weeks)

1. Delete `apps/legacy/` when every route is `new` and no importer remains
   (`grep` gate in CI + knip/dead-code check).
2. Remove `layoutManager.modern`, the ViewManager bridge in `components/Page.tsx`,
   and the jQuery/`emby-*` element leftovers that are now unused.
3. Ship the `#/` → `/` redirect table; keep it one release.
4. Rewrite `SCREEN_FEATURES_INVENTORY.md` as the current-state map (post-rewrite)
   or delete it in favour of `docs/route-registry.json`.

**Gate 10:** bundle sinks ≥ 40% vs Phase 0 baseline (or the agreed target);
zero references to `viewManager`; old bookmarks resolve.

### Phase 11 — Hardening & rollout (2 weeks)

Perf budgets enforced in CI, a11y audit on the 12 pilot routes, off-line/service
worker behaviour, embedded-webview smoke (Android/iOS webview, TV browser),
staged rollout with per-route kill switches, then removal of flags.

## 9. Risk register

| Risk | Impact | Mitigation |
|---|---|---|
| C1 (static distribution) is decided late | A whole option family (C/D) is chosen then invalidated | Resolve distribution question **in Phase 1**, as an ADR with an owner outside this repo |
| Legacy tail is underestimated | Schedule slip of weeks | Port `/details`, `/queue`, `/video` first as vertical slices, not last |
| No test safety net | Silent parity regressions | Phase 0 smoke suite is a hard prerequisite for Phase 2 |
| Focus/TV regressions from partial rendering | Unusable on TV clients | S5 spike + per-phase D-pad gate; treat focus as a feature, not polish |
| Auth adapter scope creep | Rewrites connection manager | Adapter wraps, never reimplements; Quick Connect stays in `lib/jellyfin-apiclient` |
| i18n forked by server rendering | Translation pipeline breaks | Strings stay JSON; server templates read the same files (spike S3) |
| Bundle grows during transition | Worse product while rewriting | Dual-app budget; old app's dead routes removed as soon as `new` routes pass |
| REA/legacy analysis gaps | Wrong assumptions about legacy coupling | Re-run `analyze_javascript_application` per legacy subdirectory (≤350 KB), record unknowns, don't infer absence |

## 10. Open questions (block Phase 2)

1. **Distribution:** may the web client ship a server process (sidecar BFF), or
   must it stay a static asset folder consumed by the Jellyfin server and
   third-party webviews? This single answer selects A/B vs C/D.
2. **Scope:** full parity including dashboard, or user-facing routes only with
   the dashboard kept on the current stack?
3. **TV/low-end target:** what device profile defines the perf budget
   (e.g. 2019 Android TV box, 2 GB RAM)?
4. **URL scheme:** are path-based URLs required (SEO/bookmarks/analytics), or is
   `#/` acceptable long-term?
5. **Retirement:** is deleting jQuery/ViewManager a goal itself (maintenance), or
   only a consequence?
6. **Upstream:** does this fork intend to keep merging `jellyfin-web` upstream
   (affects how much of the legacy tree can be rewritten vs. deferred)?
